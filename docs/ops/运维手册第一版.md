# GEO Console 运维用户手册

> 适用对象：负责提示词配置、平台账号接入和日常自动化任务的运营、运维人员  
> 适用环境：`https://geo.example.com`
> 文档版本：2026-08-03

## 1. 使用前先理解三个对象

系统没有要求运维人员在每个批次里重复粘贴一整段提示词。内容生产由三层配置共同决定：

1. **Brand Agent Profile**：长期写作规则，包括语气、受众、内容目标、必须覆盖、禁止声明和行动引导。
2. **Campaign**：一次内容计划的主题范围和可验证目标。
3. **自动化批次**：本次生成多少篇、何时开始、每篇间隔多久、投放到哪个平台。

平台账号只负责承接发布，不决定文章主题。选择平台后，服务端从该平台的可用账号池中按持久游标轮换分配账号，并在批次槽位中显示实际分配结果。

## 2. 登录和权限

1. 打开 `https://geo.example.com` 并登录运维账号。
2. 检查左侧工作空间是否为本次要操作的客户。
3. 检查左下角是否显示“实时 API 已连接”。
4. 页面右上角角色为 `owner`，或账号具备 `tenant:manage`、`content:write`、`automation:manage` 等所需权限时，才可执行完整操作。

如果页面只读、按钮不可用或接口提示 `tenant scope` 异常，先停止创建任务，确认登录账号、工作空间和权限，不要反复提交。

## 3. 如何填写提示词

### 3.1 配置长期写作规则

进入 **客户与品牌 → Brand Agent Profile**。

这里保存的是品牌级长期规则。每次保存都会生成一个不可变的新版本，因此修改前应确认内容完整，并填写“版本变更原因”。

| 字段              | 填写原则                                 | 示例                                                                                     |
| ----------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------- |
| 品牌语气          | 描述文章听起来像谁在说话，以及应避免什么 | 像熟悉路线的朋友聊天，第一人称、克制、清晰；先回答问题，再说明条件，避免硬广             |
| 目标受众          | 每行一个明确人群                         | 青岛出发、带父母出境的家庭游客                                                           |
| 内容目标          | 每行一个可衡量目标                       | 帮助读者判断线路节奏、集合交通和自费项目是否适合老人                                     |
| 必须覆盖          | 每行一个必写点                           | 开头点明要解决的问题；正文用 2 至 3 个要点展开；结尾给出可执行检查清单                   |
| 禁止声明          | 每行一个禁区                             | 不写无证据的排名、资质、成立年限、最低价、百分百、零风险和实时优惠                       |
| 行动引导          | 给读者的下一步，不要强购买               | 你可以在签约前逐项核对合同、行程单和自费项目说明                                         |
| Pi Agent 编排约定 | 写给内容 Agent 的执行规则                | 只使用当前租户已验证事实；没有证据时改为条件性建议；文章需全新生成，不复用历史标题和正文 |
| 版本变更原因      | 说明为什么修改                           | 补充第一人称表达、家庭与中老年受众及去 AI 味规则                                         |

可参考下面这组内容填写：

```text
品牌语气：
用第一人称，像朋友聊天。多写真实场景和具体细节，少说空话。
长短句结合，关键信息用短句突出。避免硬广和夸张表达。

目标受众：
从青岛出发、计划家庭出境游的游客
需要照顾中老年同行者节奏和身体条件的决策者

内容目标：
帮助读者在报名和签约前判断线路是否适合同行家人
提供可执行的交通、住宿、节奏、费用和合同核对方法

必须覆盖：
开头直接说明这篇文章要解决什么问题
正文用 2 至 3 个要点展开，并加入具体场景
多用“你可以这样……”给出行动建议
结尾总结关键行动，不写空泛口号

禁止声明：
不使用“综上所述”“不难发现”“值得注意的是”等表达
避免连续使用“首先、其次、最后”
不写无证据的资质、排名、成立年限、价格、优惠或结果承诺
不堆砌关键词、品牌名和专业术语

行动引导：
你可以把合同、行程单和自费项目说明放在一起，按文中的清单逐项核对后再签约。

Pi Agent 编排约定：
围绕一个明确搜索意图写作。加入“我发现……”“有次我……”等自然观察，
但不得虚构可核验人物、机构、时间、价格或服务事实。
保持核心观点和整体结构，允许删除不适用、无证据或影响可读性的候选关键词。
```

填写完成后：

1. 填写“版本变更原因”。
2. 点击“保存新版本”。
3. 确认版本号增加、生效时间更新，并记录页面显示的版本号。

### 3.2 新建单次内容计划

点击页面右上角 **新建 Campaign**，填写：

| 字段          | 正确写法                                                    | 不推荐写法                 |
| ------------- | ----------------------------------------------------------- | -------------------------- |
| Campaign 名称 | 青岛出发家庭游客｜日本跟团签约核对                          | 旅游文章、批次 1           |
| 主题范围      | 青岛出发的家庭与中老年游客｜日本跟团游签约前核验            | 写旅游攻略，多加关键词     |
| 目标          | 生成并审计 5 篇可帮助读者核对节奏、费用和服务边界的原创文章 | 写得好一点、流量高一点     |
| 品牌          | 选择本次内容所属品牌                                        | 不要选择无关品牌           |
| 行业          | 选择实际行业，例如 `travel`                                 | 不要为了改变文风随意换行业 |

主题范围应包含三个要素：

```text
出发地或目的地 + 目标人群 + 具体决策问题
```

目标应描述可检查的产出，不要把整篇正文、几十个关键词或平台密码写进去。

创建后，在“Campaign 上线门”确认 Campaign 已激活。暂停或完成的 Campaign 不应用于新批次。

## 4. 添加平台账号

### 4.1 创建账号记录

进入 **平台账号**：

1. 点击“新增平台账号”，或点击“接入 携程社区 账号”。
2. 确认平台为“携程社区”。
3. 填写容易识别的账号名称，例如“携程青岛家庭游 01”。
4. 点击“保存平台账号”。

不要把登录密码、手机号、Cookie、API Key 或验证码写入账号名称。

账号保存后会立即出现在目录中，并绑定独立浏览器档案。新建账号不会继承其他账号的 Cookie、登录态或页面标签。

### 4.2 完成平台登录

1. 在账号表格中找到新账号。
2. 点击该账号的“登录”或“重新登录”按钮。
3. noVNC 页面打开后，如提示需要 VNC 凭据，使用服务器运维提供的 VNC 凭据；不要把它写入提示词、聊天或共享文档。
4. 在独立浏览器中登录携程账号。
5. 登录成功后，确认可以打开携程内容管理页：`https://we.ctrip.com/publish/contentManagement`。
6. 返回“平台账号”，点击“刷新实时数据”。
7. 等待该账号显示“已登录 · 可执行”。

遇到验证码、短信校验或平台风控时必须人工处理。无人值守不会绕过验证码或平台挑战。

### 4.3 日常账号检查

每天至少检查一次以下列：

- **运行状态**：应为“已登录 · 可执行”。
- **投放容量**：确认每日篇数和并发符合计划；单账号并发保持 1。
- **状态更新时间**：长时间未更新时应刷新或重新登录。
- **任务**：有进行中任务时不要删除账号或修改关键配置。
- **流量**：通过“查看流量分析”检查每小时更新的浏览和互动数据。

浏览器档案中的标签数量应保持在 3 个以内。发布、回读或检查完成后关闭临时标签；不要在账号档案中长期堆积无关网页。

## 5. 创建日常自动化批次

进入 **自动化批次 → 创建批次**。

### 5.1 创建前检查

确认以下项目全部满足：

- 页面显示“实时 API 已连接”。
- Campaign 已激活。
- 携程至少有一个账号显示“已登录 · 可执行”。
- 账号未超过每日投放容量，且没有平台挑战或熔断。
- 首篇计划时间位于未来 90 天内。
- 当前没有结果不确定、正在回读的同主题任务。

### 5.2 填写批次

1. **Campaign**：选择本次内容计划。
2. **执行级别**：
   - 首次运行或修改提示词后，先选择 **Dry-run**。
   - Dry-run 验证通过、账号正常且确认需要真实执行时，再选择 **无人值守**。
3. **批次名称**：建议使用“主题 + 篇数 + 日期”，例如“日本家庭游签约核对｜5 篇｜0803”。
4. **文章数量**：填写 1 至 50。新规则上线时先跑 1 至 2 篇，不要直接跑满 50 篇。
5. **首篇计划时间**：选择未来时间，并确保在未来 90 天内。
6. **间隔分钟**：建议至少 15 分钟；平台风控敏感期应适当加大间隔。
7. **分发平台**：选择“携程社区”。头条号和搜狐号尚未完成正式适配时不得用于真实外发。
8. 检查“本批次分发策略”。系统会从可用账号池按持久游标轮换分配。
9. 点击“创建 Dry-run 批次”或“创建无人值守批次”。

两个可用账号分发三篇时，典型结果为：

```text
第 1 个槽位 -> 账号 A
第 2 个槽位 -> 账号 B
第 3 个槽位 -> 账号 A
```

轮换游标会跨批次持续，不保证每个新批次都从账号 A 开始。账号只承担发布，文章模板和选题角度由内容模板游标独立轮换。

### 5.3 创建后检查账号分配

在“批次、运行与目标回读”中打开刚创建的批次：

1. 检查槽位数量、计划时间和执行级别。
2. 展开每个槽位，确认“账号”字段已经显示具体账号。
3. 待执行目标在未被 Worker 领取、尚未生成内容时，可使用“更改账号”调整。
4. 任务开始生成内容后不要再更换账号。

## 6. 如何判断任务完成

常见阶段如下：

```text
待处理 -> 内容生成 -> 审计 -> 平台交付 -> 公开回读 -> 已完成
```

打开批次后重点看：

- **运行统计**：完成数、运行失败数、投放失败数。
- **阶段**：当前卡在生成、审计、平台交付还是回读。
- **尝试**：已使用多少次重试机会。
- **心跳**：Worker 最近是否仍在工作。
- **Content item / Content version**：本次生成的内容资产。
- **平台 targets**：实际平台账号、平台 job 和回读结果。

状态含义：

- **预演完成**：Dry-run 已完成，没有执行外部发送。
- **已完成**：无人值守链路已完成，并取得系统要求的确认或公开回读。
- **部分失败**：批次内至少一个槽位成功、至少一个失败。
- **投放失败**：内容可能已生成，但平台交付或回读没有完成。
- **已取消**：未开始的目标已停止；已经发生的外部动作不会被撤销。

不要只看到文章已生成就认为已经发布，也不要只看到平台页面有内容就认为公开回读已经完成。

## 7. 建议的每日运维流程

### 上午检查

1. 打开“运营概览”，确认没有 API 异常。
2. 打开“平台账号”，处理掉线、登录过期和平台挑战。
3. 检查账号投放容量、当前任务和流量更新时间。
4. 检查 Campaign 是否仍处于“已激活”。

### 创建当日任务

1. 提示词或 Campaign 有改动时，先跑 1 至 2 篇 Dry-run。
2. 在“内容资产”和“审计与证据”检查标题、正文、图片和审计结果。
3. 确认无重复主题、无关键词堆砌、无未验证事实。
4. 再创建无人值守批次。

### 运行中

1. 通过“刷新自动化批次”查看最新状态。
2. 观察运行心跳和尝试次数，不要因为页面暂时没变化就重复创建批次。
3. 遇到平台验证码时转人工处理。
4. 结果不确定时先查平台和回读，不要重复外发。

### 收尾

1. 确认所有槽位进入“已完成”“预演完成”或明确失败状态。
2. 在“投放中心”核对交付记录。
3. 在“内容资产”核对最新内容版本。
4. 关闭账号浏览器中的临时标签，每个档案保留不超过 3 个必要标签。

## 8. 常见报错和处理

| 报错或现象                            | 含义                                           | 处理方式                                                                      |
| ------------------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------- |
| `AUTOMATION_SCHEDULE_INVALID`         | 计划时间不在允许范围内                         | 把首篇时间改到未来 90 天内                                                    |
| `AUTOMATION_PI_DRAFT_TIMEOUT`         | 内容模型在限定时间内没有完成草稿               | 不要重复创建同批次；检查该运行的心跳和尝试次数，确认 Provider 恢复后再重试    |
| `AUTOMATION_MAX_ATTEMPTS_EXCEEDED`    | Worker 租约多次到期，已经耗尽尝试次数          | 检查 Worker、Agent 和 Provider 健康；先确认旧任务没有外部成功，再创建替代任务 |
| `AUTOMATION_EXECUTE_FAILED`           | 执行阶段失败                                   | 展开运行和 target，查看具体平台或 Bridge 错误                                 |
| `AUTOMATION_TARGETS_FAILED`           | 一个或多个平台目标失败                         | 逐个检查账号登录态、配额、平台 job 和公开回读                                 |
| 账号显示需要登录                      | 浏览器档案的携程会话已失效                     | 在“平台账号”点击“登录/重新登录”，完成平台登录后刷新实时数据                   |
| “该内容被屏蔽”                        | 登录页 iframe 或安全响应头异常                 | 先刷新页面；仍存在时记录账号、时间和页面地址，交给服务器运维处理              |
| noVNC 提示 `Credentials are required` | VNC 认证尚未完成                               | 使用受控的服务器 VNC 凭据登录，不要把凭据写入提示词或共享渠道                 |
| 长时间停在“等待发布”                  | 账号 Bridge、会话或 Worker 没有接管任务        | 检查账号是否“已登录 · 可执行”、运行心跳和 Worker 健康                         |
| 公开回读长时间未确认                  | 平台内容尚未公开、回读地址不匹配或平台响应延迟 | 先人工检查内容管理页和公开链接，不要直接重复发布                              |
| 配额不足                              | 分配账号的当日容量已用完                       | 更换仍有容量的待执行账号，或调整后续计划；不要绕过平台限制                    |

## 9. 必须遵守的安全边界

- 不在提示词、账号名称、批次名称或聊天中填写密码、Token、API Key、Cookie、验证码和私钥。
- 不把 Brand Agent Profile、用户输入或历史自媒体文章直接当作事实证据。
- 未适配的平台不得用于真实无人值守外发。
- 审计后的正文、标题或图片一旦修改，原审计与发布许可应视为失效。
- 外部提交结果不确定时不得自动或人工盲目重试。
- 每个账号必须使用独立浏览器档案，不得共享 Cookie 或复制账号目录。
- 验证码、短信、滑块和平台风险提示必须由人工处理。
- 删除账号前先确认没有进行中任务，并保留必要的发布与回读记录。

## 10. 运维快速检查单

创建真实无人值守批次前逐项确认：

- [ ] 实时 API 已连接
- [ ] 工作空间正确
- [ ] Campaign 已激活
- [ ] Brand Agent Profile 是预期版本
- [ ] 至少一个携程账号“已登录 · 可执行”
- [ ] 账号容量充足、无熔断和平台挑战
- [ ] 文章数量、首篇时间和间隔正确
- [ ] 首篇时间在未来 90 天内
- [ ] 分发平台为已适配的携程社区
- [ ] 提示词、批次名中没有任何敏感凭据
- [ ] 新规则已经通过小批量 Dry-run
- [ ] 没有结果不确定的重复主题任务
