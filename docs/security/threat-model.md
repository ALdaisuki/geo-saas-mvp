# Threat Model

Status: MVP snapshot, 2026-07-16. Review whenever a live connector, provider adapter, administrative API, new industry pack or public ingress is added.

## Assets and trust boundaries

Protected assets include tenant identity and memberships, partner contact facts, evidence content, session/CSRF/MCP tokens, platform/provider credentials, immutable variants, audit artifacts, one-time publication grants, outbox jobs, receipts and visibility observations.

Primary boundaries are:

1. browser/TLS ingress -> Nginx -> API;
2. MCP/agent-run bearer client and background Producer -> agent-MCP static tool and restricted Pi runner surface -> API session;
3. API/worker login roles -> PostgreSQL NOLOGIN roles and forced RLS;
4. worker -> connector -> external platform;
5. fixture/manual/provider evidence -> scoring and circuit decisions;
6. API/agent-MCP -> external Plastic Promise MCP governance endpoint;
7. admin/migration/bootstrap/backup plane -> application plane;
8. persisted automation batch -> actor-bound lease/heartbeat/checkpoint -> publication job readback.
9. operator-authenticated headed Chromium -> loopback CDP read-only review -> sanitized Ctrip surface evidence.

Pi Agent v0.73.1 has no built-in MCP. The Compose topology starts `agent-mcp`, whose single HTTP process embeds the GEO MCP server, a restricted Pi runner, and an explicitly enabled background batch Producer. Both request-driven and scheduled runs are tenant-scoped and limited to the static GEO/governance tool allowlist. The Producer adds leases, heartbeats and durable checkpoints but no broader tool authority. Real Pi mode does not add a live publishing connector or Doubao/Qwen adapter. Plastic Promise remains an external service.

## Threats, controls and residual risk

Publication governance also treats a semantically downgraded response as a compromise. During the current Plastic Promise rollout, GEO accepts `allow`, or `ask` only when its reported `trust_score` is finite and strictly greater than zero. Explicit `deny` and non-positive or missing trust on `ask` remain terminal. The response must name exactly `geo_publication_request`, classify it as `high` or `critical`, retain a positive manifest trust requirement, and provide a matching manifest whose side effects include `external_publish`; otherwise the request fails closed before grant, job, or outbox mutation.

The Bridge `browser_preflight` process adds a second isolation boundary: it requires
exactly one tenant, exposes no simulator page, supports only `prepare`, and rejects
`submit`/`readback` before permit consumption. This narrows the process surface but
does not turn CDP evidence into publication authorization.

New prepare observations are transactionally bound to the handoff as an outcome,
evidence kind/hash and observation time; prepared drafts also bind the media-manifest
hash. The audit row uses the top-level evidence hash. Pre-migration rows remain null
and are never upgraded from weaker state or session-hash evidence.

## Release blockers for live publication

Unattended external writes remain blocked until all of the following are independently verified:

- platform capability evidence passes [platform-onboarding.md](../api/platform-onboarding.md);
- a connector contract covers publish, timeout ambiguity, status/readback, idempotency and credential revocation;
- operator provisioning, secret management, TLS, rate limiting and audit export are operational;
- worker identity resolves to a per-tenant least-privilege service principal and Kill Switch scope tests pass on real PostgreSQL;
- backup restore and incident stop/resume are rehearsed;
- fixture/manual/API evidence is visible and cannot be coerced into another type;
- an approved low quota canary demonstrates exact hash, receipt and readback reconciliation.

## Security verification evidence

Retain Git commit/image digest, Compose rendered config with secrets redacted, migration output, role ACL queries, two-tenant denial results, TLS/cookie/CSRF results, MCP denied-tool tests, dry-run receipt, Kill Switch test, backup restore report, platform onboarding decision and reviewer identity. A passing unit test without its environment and artifact is not commercial audit evidence.
